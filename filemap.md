# File map

- `CLAUDE.md` — project context, people, HA facts, rules / update on every status change.
- `PROMPT.md` — original brief from the user / read-only reference.
- `docs/WEBHOOK.md` — webhook transport contract for roaming machines (pairing code, signed requests, hello/snapshot/poll/ack, queue, online window) / shared by the HA integration and the plugin; touch both sides together.
- `docs/DESIGN.md` — architecture, snapshot data model, verified/assumed table, security, build steps / touch when the design or a verified fact changes.
- `docs/evidence/hooks-2.1.295-sample.jsonl` — real (pre-redacted) hook stdin payloads from Claude Code 2.1.295, one per line / add new captures when hook shapes are verified; tests replay it.
- `reference/` — reference material from other sessions / read-only.
- `.claude-plugin/marketplace.json` — marketplace "jamboard" listing the crew-hub plugin / touch when the plugin version or list changes.
- `plugins/crew-hub/.claude-plugin/plugin.json` — plugin manifest (name, version) / bump the version together with `lib/crewhub/__init__.py`.
- `plugins/crew-hub/hooks/hooks.json` — 17 hook events (incl. PermissionDenied) → `bin/crew-hook`, timeout 5; PermissionRequest timeout 65 (= max hold 55 + 10) / touch when adding or dropping an event or changing the hold limit.
- `plugins/crew-hub/bin/crew-hook` — hook entry point; thin wrapper over `lib/crewhub/hook.py` / rarely.
- `plugins/crew-hub/bin/crew-hubd` — daemon entry point; thin wrapper over `lib/crewhub/daemon.py` (`--once` runs one pass; exits at once without doing anything while another crew-hubd holds the pidfile lock) / rarely.
- `plugins/crew-hub/bin/crew-hub-pair` — pairing tool entry point (run by the person in their own terminal, never through Claude); thin wrapper over `lib/crewhub/pair.py` / rarely.
- `plugins/crew-hub/skills/crew-hub-setup/SKILL.md` — `/crew-hub-setup` (user-invoked only): checks python3, explains MQTT (`crew-hub-pair --mqtt`) vs webhook (pairing code from HA), hands the command to the person, verifies via crew-hubd.log + snapshot.json; never asks for or handles secrets / touch when pairing steps change.
- `plugins/crew-hub/lib/crewhub/__init__.py` — package marker + VERSION (0.3.1) / bump with plugin.json and marketplace.json.
- `plugins/crew-hub/lib/crewhub/paths.py` — every ~/.claude/crew-hub path incl. secrets.json and answers/<requestId>.json (dir 0700), plus ~/.claude.json (read-only trust lookup); resolved from HOME at call time / touch when adding a file.
- `plugins/crew-hub/lib/crewhub/redact.py` — the allowlist: hook payload → one spool record; `sanitize_summary` (Stop/SubagentStop msg: first line, ≤120, paths→basename, URLs→host, e-mails/token-like runs→…), `summaries=False` drops it; `questions` (AskUserQuestion: question/header/multiSelect/option labels via `clip_text` ≤200, max 4×6, descriptions dropped) / touch when a new safe field is needed; add a leak test first.
- `plugins/crew-hub/lib/crewhub/hook.py` — crew-hook body: claude pid, O_APPEND spool write, daemon liveness + detached spawn; reads config.json `summaries` only on Stop/SubagentStop (default on). PermissionRequest: requestId + questions in the record; with commands enabled + commandSecret it holds up to holdSeconds polling answers/<rid>.json (250 ms), prints the decision JSON (allow/deny+message; questions: allow + updatedInput.answers mapped back to full text), records answered/unanswered (also on SIGTERM); the only path that ever prints / touch for hook behaviour; keep imports minimal (<50 ms).
- `plugins/crew-hub/lib/crewhub/state.py` — Model: folds records into the DESIGN.md §2 snapshot, enrichment (sessions/*.json, transcript tail, plan files), `poll_plans` (plan-only sessions for sessions without hooks: `_fromPlan`, status from a live registry entry else idle, removed with the file), pruning, 40 KB cap; open requests `_reqs` (newest = session.waiting with requestId/hubCanAnswer/questions; cleared by answered, matching PostToolUse/PostToolUseFailure/PermissionDenied, Stop, UserPromptSubmit, SubagentStop, SessionEnd, or the registry going busy/idle after the request; unanswered/expired hold → hubCanAnswer false), `waiting_state` for the answer action, session.kind + session.controls / touch for snapshot fields or status rules.
- `plugins/crew-hub/lib/crewhub/spool.py` — spool tailing from a persisted (inode, offset) and safe rename-based rotation at 5 MB / touch only with the rotation race comment in mind.
- `plugins/crew-hub/lib/crewhub/mqtt.py` — minimal MQTT 3.1.1 client (CONNECT/LWT, PUBLISH QoS0/1, SUBSCRIBE, PING) / touch for protocol features.
- `plugins/crew-hub/lib/crewhub/config.py` — config.json + secrets.json loading (machine id, prefix, mqtt, contextMax; `summaries` is documented here but read by hook.py); MQTT password from secrets.json `mqttPassword` first, legacy config.json mqtt.password second; `load(migrate=True)` (daemon start) moves a legacy password into secrets.json and rewrites config.json without it; never logs a secret, topic names, ctx max rules; `commands` block (enabled, folders {key: path,label}, models, permissionModes, holdSeconds 0..55; active only with secrets.json commandSecret; `public()` = keys/labels, no paths); `transport` mqtt (default; anything but "webhook") | webhook: `webhook.url` (https only; http only for a loopback host with env CREWHUB_TEST_ALLOW_HTTP=1, tests) + secrets.json `webhookId` + `commandSecret` → `cfg.webhook` {scheme, host, port, base, id, secret}, else `webhook_error` (log-safe); `linked` = mqtt or webhook / touch for new settings.
- `plugins/crew-hub/lib/crewhub/daemon.py` — crew-hubd main loop, `self.link` = MqttLink (backoff) or webhook.WebhookLink (same start/step/publish/publish_acks/offline surface), plans-dir poll every 2 s, snapshot/state writes, pidfile lock, signals; cmd messages → commands.CommandHandler, acks published from the main thread on `<prefix>/<m>/ack`; machine.commands; sweeps answer files older than 10 min / touch for publish cadence or command wiring.
- `plugins/crew-hub/lib/crewhub/webhook.py` — docs/WEBHOOK.md machine side: canonical + HMAC envelope, Http (http.client keep-alive, ssl.create_default_context(), no redirects, one retry on a dropped idle connection, 200 + non-JSON = unknown webhook), WebhookLink: sender thread (hello once, acks first (60 s TTL), latest snapshot only, backoff to 60 s, flush ≤5 s on stop) + poll thread (back-to-back polls, 35 s timeout, envelopes → main thread → CommandHandler.receive(retain False)); logs host/status/error type only, never id/path/secret/signature / touch with WEBHOOK.md.
- `plugins/crew-hub/lib/crewhub/pair.py` — crew-hub-pair: pairing code via getpass, kind from its "t" (none = webhook); "t": "mqtt" (0.3.1) replaces only secrets.json commandSecret when config.json is already MQTT for that machine id (else PairError, nothing written), prints "new command secret installed for <m>"; webhook (code `crewhub1:` + base64url JSON validated, writes config.json/secrets.json 0600 in a 0700 dir keeping other keys, signed hello, "paired as <m> with <host>") or `--mqtt` (prompts, getpass for password/secret; empty = keep saved; switching from webhook drops webhookId + its commandSecret); `--name`, `--no-daemon`, hidden `--stdin` (tests); restart = SIGTERM via pidfile, wait for the pidfile lock, hook.spawn_daemon; never echoes the code or a secret / touch with WEBHOOK.md pairing.
- `plugins/crew-hub/lib/crewhub/commands.py` — signed commands (docs/COMMANDS.md): canonical JSON + HMAC verify (constant time), retained/stale ±60 s/replay 10 min/disabled checks, per-action arg validation, Executor (send via inbox, answer file, interrupt = `claude attach` in a pty + one ESC, stop = `claude stop`, start = `claude --bg --remote-control … -- <prompt>` in a trusted preset folder), one worker thread, ack queue; logs action/id/outcome only / touch with COMMANDS.md.
- `plugins/crew-hub/lib/crewhub/inbox.py` — session registry (~/.claude/sessions/*.json): procStart liveness, kind (bg|interactive|print), key file `<pid>.<sha256(socket)>.key` with procStart check, inbox auth + one frame / touch when the peer protocol changes.
- `card/crew-hub-card.js` — Lovelace card rendering machine snapshots in the Crew Board v4 look (no deps, textContent only) / touch for card UI. (entry restored by the reporter worker; owner: card step)
- `card/preview.html` — standalone preview page loading the card / touch with the card.
- `card/preview-hass.html` — preview with a fake hass: subscribeMessage delivers the fixture as "full", then a "machine" update after 2 s and every 1 s; sendMessagePromise answers crew_hub/command after 600 ms (error no_ack for the session named "error demo"); `?refuse=1` shows the not-available notice / touch with the card's feed or command code.
- `card/verify-controls.js` — Playwright check of the card controls on preview-hass.html (draft/focus/caret survive re-renders, send/answer/two-tap/start shapes, feedback, 390 px overflow, ≥40 px targets, no console errors) + card-controls-390/1280.png; run `pw-node card/verify-controls.js` / touch with the card's controls.
- `README.md` — overview + Install (HACS/manual, add integration, machines, dashboard) + Roaming machines (webhook: pairing, re-pair, behaviour, reverse proxy needs) + Commands + dev commands / touch when install steps change.
- `hacs.json` — HACS metadata (name, render_readme) / rarely.
- `scripts/sync-card.sh` — copies card/crew-hub-card.js into custom_components/crew_hub/www/ / run after every card edit.
- `custom_components/crew_hub/manifest.json` — integration manifest (mqtt + webhook dependencies, version 0.3.1, single_config_entry) / bump version with const.py VERSION.
- `custom_components/crew_hub/const.py` — domain, option keys (incl. machine transport/public_url/webhook_id; no transport = mqtt), transports, hass.data keys, card URL, websocket command names, VERSION / touch with the manifest.
- `custom_components/crew_hub/store.py` — HA-free in-memory model {machine: status, snapshot, receivedAt, configured}, MQTT topic parsing, set_status/set_snapshot for webhook input, 256 KB cap, 64-machine cap, listeners, working/waiting aggregates (offline machines don't count) / touch for status rules.
- `custom_components/crew_hub/__init__.py` — entry setup: migrate secrets out of the options (secret_store.py, before the update listener exists), wait for MQTT, store + WebhookHub (both outlive reloads), one HA webhook per webhook machine (POST, local_only False; unregistered on unload), subscribe `<prefix>/+/snapshot|status|ack` (ignoring webhook machines' ids), registers services + websocket once in async_setup, static card path, card Lovelace resource (storage mode: create/update `?v=<VERSION>-<digest>` in place, drop duplicates, delete on entry removal, kept on unload; YAML mode/no lovelace/error: add_extra_js_url instead, never both), reload on options change; entry removal deletes the secrets file / touch for lifecycle.
- `custom_components/crew_hub/websocket.py` — admin-only `crew_hub/subscribe` (result, "full", then "machine" events), `crew_hub/get` and `crew_hub/command` (result {ok, error?, result?}) / touch for the card feed protocol.
- `custom_components/crew_hub/secret_store.py` — machine secrets (0.3.1): private HA Store `crew_hub.secrets` v1 `{id: {secret, webhookId?}}` in hass.data (outlives reloads), saved on every change; async_migrate_entry moves 0.3.0 options secrets into it (Store first, then options without them + has_secret; idempotent, no update when clean) and drops orphans / touch when secret storage changes; never log or return its contents.
- `custom_components/crew_hub/diagnostics.py` — config entry diagnostics: entry data/options + per-machine status summary, async_redact_data (secret, webhook_id/webhookId, sig, …) + URL paths cut; never reads the secret Store / touch when diagnostics change.
- `custom_components/crew_hub/commands.py` — signed commands per docs/COMMANDS.md (secret from secret_store.py): arg validation against the machine's snapshot (commands.enabled, session.controls, folder/model/mode allowlists), envelope + HMAC over the canonical JSON, publish `<prefix>/<machine>/cmd` QoS 1 retain False (webhook machines: WebhookHub.enqueue, queue_full when 20 are waiting), ack routing by id via resolve_ack (MQTT `<prefix>/+/ack` and webhook acks), 15 s timeout → no_ack; logs action/machine/id/outcome only / touch with COMMANDS.md.
- `custom_components/crew_hub/webhook_transport.py` — docs/WEBHOOK.md: pairing codes (t webhook|mqtt) + public URL check, request parse/verify (413 over 256 KB read with a cap; 401 for shape, m, ts ±120 s, HMAC constant-time, nonce 10 min), hello/snapshot/poll/ack, WebhookHub (per-machine queue max 20 / 60 s TTL / at most once, one held poll ≤ 25 s, newer poll releases older with [], 90 s online timer) / touch with WEBHOOK.md.
- `custom_components/crew_hub/services.py`, `services.yaml` — crew_hub.send_message/answer/interrupt/stop/start_session → commands.py; admin users only, calls without a user (automations) refused; services.yaml names/descriptions identical to strings.json "services" (Mr Manager's tools read it) / touch with commands.py and strings.json.
- `custom_components/crew_hub/config_flow.py` — config flow (prefix, single instance) + options menu add/edit/remove machine (transport mqtt|webhook; secrets go to secret_store.py, options only get has_secret; mqtt: generated secret saved at once, then step `pair_mqtt` shows the code once, or legacy typed secret ≥16 chars in the collapsed `advanced` section; webhook: public_url https without path, generated webhook id + secret saved at once, then step `pair` shows the code once; edit_machine: name, re-pair (new secret + code) or typed secret, not both; edit_webhook: name, public_url, re-pair (forces a reload); remove deletes the Store entry; init migrates an unloaded 0.3.0 entry; never pre-fills or shows a stored secret) / touch for settings.
- `custom_components/crew_hub/entity.py`, `sensor.py`, `binary_sensor.py` — device "Crew Hub"; sensor.crew_hub_working, binary_sensor.crew_hub_needs_me (attr `sessions`, unrecorded), binary_sensor.crew_hub_<id>_online; writes only on change / touch for entities.

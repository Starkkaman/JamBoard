# File map

- `CLAUDE.md` — project context, people, HA facts, rules / update on every status change.
- `PROMPT.md` — original brief from the user / read-only reference.
- `docs/WEBHOOK.md` — webhook transport contract for roaming machines (pairing code, signed requests, hello/snapshot/poll/ack, queue, online window) / shared by the HA integration and the plugin; touch both sides together.
- `docs/DESIGN.md` — architecture, snapshot data model, verified/assumed table, security, build steps / touch when the design or a verified fact changes.
- `docs/evidence/hooks-2.1.295-sample.jsonl` — real (pre-redacted) hook stdin payloads from Claude Code 2.1.295, one per line / add new captures when hook shapes are verified; tests replay it.
- `reference/` — reference material from other sessions / read-only.
- `.claude-plugin/marketplace.json` — marketplace "jamboard" listing the crew-hub and crew-flow plugins / touch when the plugin version or list changes.
- `plugins/crew-hub/.claude-plugin/plugin.json` — plugin manifest (name, version) / bump the version together with `lib/crewhub/__init__.py`.
- `plugins/crew-hub/hooks/hooks.json` — 17 hook events (incl. PermissionDenied) → `bin/crew-hook`, timeout 5; PermissionRequest timeout 65 (= max hold 55 + 10) / touch when adding or dropping an event or changing the hold limit.
- `plugins/crew-hub/bin/crew-hook` — hook entry point; thin wrapper over `lib/crewhub/hook.py` / rarely.
- `plugins/crew-hub/bin/crew-hubd` — daemon entry point; thin wrapper over `lib/crewhub/daemon.py` (`--once` runs one pass; exits at once without doing anything while another crew-hubd holds the pidfile lock) / rarely.
- `plugins/crew-hub/bin/crew-hub-pair` — pairing tool entry point (run by the person in their own terminal, never through Claude); thin wrapper over `lib/crewhub/pair.py` / rarely.
- `plugins/crew-hub/skills/crew-hub-setup/SKILL.md` — `/crew-hub-setup` (user-invoked only): checks python3, explains MQTT (`crew-hub-pair --mqtt`) vs webhook (pairing code from HA), hands the command to the person, verifies via crew-hubd.log + snapshot.json, then makes sure the plan-file rule is in ~/.claude/CLAUDE.md (`crew-hub-pair --install-plan-rule`, the one invocation Claude may run itself); never asks for or handles secrets / touch when pairing steps change.
- `plugins/crew-hub/templates/plan-file-rule.md` — text of the plan-file rule block that planrule.py puts in the user-level ~/.claude/CLAUDE.md (between `<!-- crew-hub:plan-file -->` markers, added by code) / touch when the plan file format (DESIGN.md §3) changes.
- `plugins/crew-hub/lib/crewhub/__init__.py` — package marker + VERSION (0.5.0) / bump with plugin.json and marketplace.json.
- `plugins/crew-hub/lib/crewhub/paths.py` — every ~/.claude/crew-hub path incl. secrets.json and answers/<requestId>.json (dir 0700), plus ~/.claude.json (read-only trust lookup), ~/.claude/CLAUDE.md and the plugin's templates/plan-file-rule.md; resolved from HOME at call time / touch when adding a file.
- `plugins/crew-hub/lib/crewhub/redact.py` — the allowlist: hook payload → one spool record; `sanitize_summary` (Stop/SubagentStop msg: first line, ≤120, paths→basename, URLs→host, e-mails/token-like runs→…), `summaries=False` drops it; SubagentStop `agent_transcript_path` → `atp` (local only, like `tp`); PostToolUse TaskUpdate also keeps `subject` (renames, ≤120) and input status deleted when the response has no statusChange; `questions` (AskUserQuestion: question/header/multiSelect/option labels via `clip_text` ≤200, max 4×6, descriptions dropped) ; PostToolUse TaskStop/KillShell/KillBash → `stopTask` (task_id, else shell_id; id charset only, ≤100) / touch when a new safe field is needed; add a leak test first.
- `plugins/crew-hub/lib/crewhub/hook.py` — crew-hook body: claude pid, O_APPEND spool write, daemon liveness + detached spawn; reads config.json `summaries` only on Stop/SubagentStop (default on). PermissionRequest: requestId + questions in the record; with commands enabled + commandSecret it holds up to holdSeconds polling answers/<rid>.json (250 ms), prints the decision JSON (allow/deny+message; questions: allow + updatedInput.answers mapped back to full text), records answered/unanswered (also on SIGTERM); the only path that ever prints / touch for hook behaviour; keep imports minimal (<50 ms).
- `plugins/crew-hub/lib/crewhub/state.py` — Model: folds records into the DESIGN.md §2 snapshot, enrichment (sessions/*.json, transcript tail, plan files), `poll_plans` (plan-only sessions for sessions without hooks: `_fromPlan`, status from a live registry entry else idle, removed with the file), pruning, 40 KB cap; waiting (0.4.1, module doc + DESIGN §2): open requests `_reqs` + request-less prompt `_note` + live registry status (`_regStatus`/`_regAt`/`_regWaitingFor`/`_regRead`); registry waiting = waiting, busy/idle clears within one enrich unless a hold still backs it; no registry: any progress event clears (a running hold excepted), unanswered drops, 10 min / 60 s expiry; `_pick_waiting`/`_prune_waiting`/`_refresh_waiting`; idle_prompt = idle; hubCanAnswer only while crew-hook holds; `waiting_state` for the answer action, session.kind + session.controls; 0.4.0: agent status running|done|failed|stopped + stopReason ("session restarted" on SessionStart except source compact, or the registry entry moving to a new process (`_regProc` [pid, procStart], old one gone); "inactive" after AGENT_IDLE_MS 10 min without a step while the registry status is idle or the session ended); "stopped by session" on PostToolUse TaskStop with a matching `stopTask` (not revived by a step); a step revives the others, SubagentStart any, `_prune_agents` (finished: 30 min after endedAt, max 6 newest per session, untitled 0-step dropped; running never by count; the MAX_AGENTS cap only evicts finished ones), `display_name` (registry user/auto name > newest non-derived formerNames/older entry name > plan title prefix before ":" > cwd basename + " (localName)", just localName in "project"), session.localName; plan task statuses never touched; 0.5.0 (module doc + DESIGN §2): `derive_plan`/`join_agents`/`parse_subject` (plan from the task list when there's no plan file, `plan.source` file|tasks, `_sync_plan` after every fold/enrich/plan load), `read_usage` incremental transcript usage (session.tokens main thread, agent.tokens from `_atp` or `agent_transcript`, 15 s while running, once after the end via `_tokEnd`, 4 MB/file + 16 MB/pass), `_public` strips agent `_` keys and copies plan/tokens / touch for snapshot fields or status rules.
